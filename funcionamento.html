FUNCIONAMENTO DO BACK-END

Cliente/Servidor

A estrutura de cliente e servidor é um modelo de interação no qual um programa envia uma solicitação para outro programa e aguarda uma resposta. O programa solicitante é chamado de cliente e o que responde é chamado de servidor.

Requisição e Resposta

A estrutura de cliente/servidor se comunica com mensagens que podem ser entendidas por humanos. Estas mensagens são chamadas de requisições ou respostas, tendo cada uma delas um formato.

Requsição

A primeira linha de uma requisição contém três elementos:

GET / HTTP/1.1

GET significa o método HTTP utilizado.

Ele diz que ação o cliente espera que seja executada pelo servidor. Neste caso, que ele lhe traga algo.

Após o GET, veem o caminho para qual o recurso que estamos buscando no servidor. Por exemplo, se desejamos acessar a página de contatos de um site, esse caminho seria contatos.html. Logo após o caminho temos a versão do protocolo HTTP utilizada. nesse caso, a versão utilizada é a 1.1, a mais comum atualmente. Uma requisição também pode conter cabeçalhos, que apresentam informações adicionais.

Host: devmedia.com.br User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/67.0.3396.99 Safari/537.36…

Dependendo do método HTTP utilizado, a requisição também pode ter um corpo. O corpo de uma mensagem nos permite enviar dados para o servidor. quando usamos o método GET, por exemplo, a mensagem não necessita de um corpo, pois os dados já estão contidos na URL. Já no POST, dizemos que os dados preenchidos em um formulário são passados por um corpo da requisição.

Resposta

Uma resposta possui a seguinte estrutura:

HTTP/1.1 200 OK Cache-Control: no-cache, must-revalidate Content-Type: text/html; charset=ISO-8859-1 …

A primeira informação que identificamos na linha 1 contém a versão do protocolo HTTP utilizado. Após isso,vemos o código de retorno e seu significado. 200 significa que a requisição foi recebida e processada pelo servidor com sucesso. Temos abaixo desta linha os headers da resposta, a exemplo Cache-Control e Content-Type. A resposta também pode conter um corpo com o recurso acessado no servidor.

HTTP e HTTPS

O protocolo de transferência de hipertexto (HTTP) utiliza o modelo de comunicação cliente/servidor. Ele é um protocolo de aplixação no modelo de comunicação de rede Opens Systems Interconnection (OSI). Ele define vários tipos de solicitações e respostas. Da mesma forma que o servidor envia diferentes tipos de protocolo HTTP na forma de códigos numéricos e dados.

200 - OK 400 - Solicitação inválida 404 - Recurso não encontrado

Essa comunicação de solicitação/resposta geralmente é invisível para os usuários. è um método de comunicação que o navegador e os servidores usam, então o WWW (World WIde Web) funciona de forma consistente para todo No entanto, o protocolo HTTP não criptografa as informações que ele transmite, permitindo que as informações sejam lidas por terceiros. Este não era o processo ideal, então foi estendido para HTTPS, que combina as solicitações respostas com a tecnologia SSL e TLS Os sites HTTPS devem obter um certificado SSL/TLS de uma autoridade de certificação (CA) independente Esses sites compartilham o certificado com o navegador antes de trocar dados para estabelecer confiança. O certificado SSL também contém informações criptográficas, para que o servidor e os navegadores da Web possam trocar dados criptografados ou codificados.

  1. O navegador tenta verificar a autenticidade do site solicitando o certificado SSL do servidor
  2. O servidor envia o certificado SSL que contém uma chave pública de resposta.
  3. O certificado SSL do site comprova a identidade do servidor. Quando o navegador estiver satisfeito, ele usará a chave pública para criptografar e enviar uma mensagem que contém uma chave para uma sessão secreta.
  4. O servidor Web usa sya chave privada para descriptografar a mensagem e recuperar a chave da sessão. Em seguida, ele criptografa a chave da sessão e envia uma mensagem de confirmação ao navegador.
  5. Após este processo, o navegador e o servidor Web mudam para usar a mesma chave de sessão para trocar mensagens com segurança.
