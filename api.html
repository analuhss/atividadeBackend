O que são APIs

Para que serve uma API?

Ela serve para garantir que um sistema com linguagem diferente possam se integrar de maneira ágil e segura.

O que é uma API REST?

Uma API REST é uma interface de programação de aplicativos (API) que segue os princípios de um design do estilo arquitetônico REST (transferência de estado representacional), utilizado para conectar sistemas hipermídia distribuídos. Em seu nível mais básico, uma API é um mecanismo que permite que uma aplicação ou um serviço que acessa os recursos é o cliente e a aplicação ou serviço que contém o recurso e o servidor.

O que é um ENDPOINT?

Um endpoint de uma API é um local digital onde uma API faz solicitações para seu servidor. Os endpoints de APIs são componentes de APIs e , geralmente, estão na forma de URLs ou localizadores de recursos online. Esses endpoints funcionam um pouco como os números de telefone: assim como um número de telefone para entrar em contato com uma determinada pessoa ou empresa, os clientes API (o software que faz uma chamada de API) fornecem URL de endpoint para acessar em um recurso específico. Uma URL endpoint fornece o local de um recurso em um servidor de API e ajuda a conectar o cliente de API ao recurso que está sendo solicitado. Basicamente, ele diz ao servidor: “o recurso que eu preciso está localizado aqui”.

Como o Front-End utiliza uma API

Uma estrutura importante na na comunicação do frontend com uma API é um API Gateway. Ele é comum em sistemas distribuídos e microsserviços. No front-end, o API Gateway pode ser visto como um intermediário entre o cliente(front-end) e o backend (onde as APIs estão implementadas). A função dessa estrutura é simplificar e centralizar a comunicação com várias APIs, proporcionando diversas funcionalidades. No front end, você raramente interage diretamente com uma API gateway. Em vez disso, você faz chamadas para URLs que o gateway expõe. O gateway processa essas requisições e as redireciona para os serviços apropriados no back-end, simplificando a lógica do cliente. Outra tecnologia utilizada é o Handler, que é um termo genérico que se refere a uma função ou método responsável por tratar ou gerenciar eventos ou requisições. No contexto de consumo de API no front-end, um Handler geralmente se refere a funções que manipulam e processam a resposta da API. E eles podem ser divididos em dois tipos principais.

  • Handler de requisição: este é o código que dispara a requisição para a API. ele pode ser um fetch, axios ou outro método usado para enviar a requisição HTTP ao servidor . No handler de requisição, você pode configurar parâmetros de requisição, como cabeçalhos, método HTTP, parâmetros da URL, e dados no corpo da requisição.
  • Handler de resposta: após a requisição ser enviada, um handler de resposta é responsável por processar que acontece quando a resposta chega ao frontend. Ele lida com o sucesso ou falha da requisição.
